# Журнал изменений

## 1.2.1 — 30.03.2026

### Уведомления
- Во вкладке `Каналы -> История доставок` типы событий и статусы доставки переведены на i18n-ключи (вместо сырых кодов `accesses.*`, `up/down`, `sent/failed/...`).

### Локальные проверки и тесты
- Добавлены и закреплены локальные проверки i18n:
  - поиск ключей, которые есть только в `ru.json` или только в `en.json`,
  - поиск ключей, используемых в `gui/static/*.js,*.html`, но отсутствующих в одном или обоих словарях.
- Добавлена проверка покрытия API-документации по вкладкам меню:
  - список вкладок берется из `MENU_ORDER` (`gui/static/js/app.js`),
  - для каждой вкладки проверяется наличие обязательных API-префиксов в `docs/ru/api.md` и `docs/eng/api.md`.
- Добавлен `permission matrix` тест для zero-trust на уровне API guards:
  - роли без требуемых прав получают `403`,
  - доступ разрешается только ролям с нужным permission (включая `requireAnyPermission`-сценарии).
- Добавлены UI contract tests:
  - проверка соответствия табов/роутов/placeholder-страниц,
  - проверка базовых селекторов и i18n-маркеров для ключевых вкладок.
- Добавлены polling resilience tests:
  - проверка остановки polling при ожидаемых фоновых ошибках (`401`, network, service unavailable),
  - проверка отсутствия interval-автоспама в overview бэкапов.
- Добавлены persistence tests:
  - сохранение данных после restart-эквивалента,
  - очистка данных после `-v`-эквивалента (удаление volume/data-root),
  - проверка volume-монтажа состояния в `docker-compose.yaml`.
- Добавлены migration tests (`latest-1 -> latest`) с проверкой:
  - применимости апгрейда,
  - сохранности ранее записанных данных,
  - совместимости модульного хранилища после апгрейда.
- Добавлены API schema contract tests для ключевых endpoint’ов:
  - контроль обязательных top-level полей,
  - контроль ожидаемых типов полей,
  - контроль отсутствия неожиданных ключей (где применимо).
- Добавлены audit contract tests для критичных действий:
  - проверка корректных `actor/action/details` для `Доступов`,
  - проверка логирования обновления настроек уведомлений и отправки событий доступов.
- Добавлены i18n runtime tests:
  - проверка разрешения runtime-ключей RU/EN для меню и описаний страниц,
  - проверка пути переключения языка (`load/apply/renderMenu/loadPage`) без «сырых» ключей в UI.
- Добавлены security negative tests:
  - CSRF отсутствует -> `reject` (`403`),
  - невалидная сессия -> `401`,
  - step-up-required endpoint без step-up -> `deny` (`403`).
- Добавлен единый make-target для enterprise gate:
  - `make test-enterprise` запускает полный и фокусный критичный тестовый контур.
- Добавлен PowerShell-скрипт enterprise gate для Windows:
  - `scripts/ci/test_enterprise.ps1` (эквивалент полного набора проверок без зависимости от `make`).
- Уточнен единый локальный запуск тестов через `go test ./...` для Windows:
  - добавлена рекомендация использовать локальный `GOCACHE` в репозитории, чтобы избежать `Access is denied` в системном build-cache.
- Локальные правила усилены до hard-gate:
  - добавлен блокирующий anti-`localStorage/sessionStorage` diff-check (новые browser-ключи требуют обязательного обоснования),
  - проверка UTF-8/mojibake зафиксирована как обязательный CI-gate с фейлом сборки при нарушении.
- Добавлен CI-скрипт `scripts/ci/encoding_gate.ps1`:
  - проверяет diff на новые `localStorage/sessionStorage` (блокирует без явного обоснования),
  - проверяет измененные текстовые файлы на невалидный UTF-8 и символы mojibake (replacement char `U+FFFD`).

### Отчёты и интерфейс
- Автоматизировано заполнение отчётов при создании из шаблона:
  - если в шаблоне есть маркеры секций `<!-- SECTION: ... -->`, данные по секциям (`доступы`, `инциденты`, `аудит`, `задачи`, `документы` и др.) автоматически подтягиваются из БД и подставляются в шаблон при создании отчёта;
  - шаблон теперь используется как оформитель/каркас, а не только как пустая разметка.
- Улучшена локализация шаблонов отчётов:
  - для tagged-шаблонов (`EXECUTIVE_*`, `ACCESS_*`) добавлены локализованные названия в списках и селекторах RU/EN.
- Унифицирована сортировка таблиц по всему приложению:
  - сортировка по клику работает единообразно и повторно применяется после перерисовки данных (включая вкладку `Логи`).
- Для модалок `Доступов` добавлено быстрое добавление сервиса по `Enter`:
  - при вводе нового сервиса в поле поиска он добавляется в каталог и сразу выбирается;
  - дубликаты предотвращаются.
- Экспорт отчётов приведён к поведению `Документов`:
  - выгрузка выполняется через `fetch` + `blob` с корректным именем файла из `Content-Disposition`,
  - исправлены кейсы с некорректным открытием/скачиванием через popup.
- В режиме просмотра отчёта добавлен запрет копирования содержимого:
  - блокируются `copy/cut/context menu` и сочетания `Ctrl/Cmd + C/X/A`,
  - добавлено уведомление в UI о запрете копирования.
- Переработана секция `Доступы` в автогенерации отчётов:
  - источник данных переключён на актуальный срез `accesses.data` (а не актор из audit),
  - добавлены блоки `Top services` и `Users and services` (сервисы по каждому пользователю),
  - исправлен кейс, когда в отчёте показывался `admin` вместо целевого пользователя.
- Для секции `Связанные аудиты` добавлена фильтрация и локализация:
  - для шаблонов доступов автоматически включается режим `related_to=accesses`,
  - исключены шумовые события (`report.list`, `report.template.list`, `doc.list`, `folder.list`, и т.д.),
  - action/details в отчёте отображаются в локализованном виде (RU/EN) для ключевых событий доступов.
- Скорректировано позиционирование окна просмотра/редактора отчёта:
  - панель поднята выше и выровнена по UX-паттерну документов, без перекрытия верхних вкладок.
  - окно закреплено при открытии отчёта (фиксированное позиционирование + блокировка прокрутки страницы).
- Поведение вкладок отчётов приведено к UX документов:
  - просмотр/редактирование отчёта открывается в отдельной закрываемой вкладке внутри `reports-tabs`, а не поверх главной панели;
  - добавлены закрываемые вкладки отчётов (`x`) с корректным роутингом `/reports/{id}` и `/reports/{id}/edit`.

### Безопасность
- В `Настройки -> Укрепление безопасности` добавлены два админ-флага DLP:
  - `Запретить копирование защищенного контента`;
  - `Пытаться блокировать скриншоты`.
- Оба флага по умолчанию включены (`true`) и сохраняются на backend.
- Настройки применяются к защищенным документам и отчетам: копирование и попытка скриншота теперь управляются раздельно.
- Добавлен отдельный `DLP фрейм` в укреплении безопасности:
  - режим применения блокировок: `ко всем документам/отчетам` или `только защищенные (гриф/теги)`;
  - выбираемая область действия (scope): `Документы` и/или `Отчеты`.
- Усилен фактический запрет копирования в просмотре и редактировании документов/отчетов:
  - перехватываются `copy/cut/context menu` и сочетания `Ctrl/Cmd + C/X/A`;
  - добавлен дополнительный глобальный перехват на уровне документа/окна для снижения обходов.
- Улучшены DLP-сигнатуры для поведенческой модели:
  - события `copy_blocked` и `screenshot_attempt` пишутся в `user_behavior_events` как `dlp.copy_blocked` и `dlp.screenshot_attempt`;
  - сигнатуры добавлены в анализ активности (`Настройки -> Укрепление безопасности -> Анализ активности`).
- Усилена реакция на попытки скриншота в защищенных режимах просмотра/редактирования:
  - при срабатывании DLP-сигнатуры включается экранная privacy-маска, скрывающая интерфейс на короткий интервал.
