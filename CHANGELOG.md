# Журнал изменений

## 1.2.0 — 27.03.2026

### Доступы
- В формах `Создать`, `Редактировать` и `Дополнить` для поля сервисов добавлен встроенный поиск по названию.
- Списки сервисов в выборе отсортированы по алфавиту с корректной сортировкой RU/EN.
- Поиск по сервису на главной странице `Доступов` переработан:
  - компактный выпадающий список,
  - скролл при длинном списке,
  - стилизация под текущий интерфейс.
- Основной фрейм экрана `Доступы` приведен к визуальному шаблону `Настроек`.
- Добавлена кнопка `Увольнение` в строках пользователей: фиксирует событие в истории доступа и формирует уведомление с датой увольнения и днем недели.
- Для `Увольнения` ввод даты переведен в модальное окно с календарем (в стиле формы инцидентов), дата/день недели отображаются с учетом i18n.
- Переключатель `Включить уведомления для доступов` убран из вкладки `Доступы`: управление перенесено в `Уведомления -> Настройки`.
- Удалено клиентское хранение данных `Доступов` в `localStorage`; источник данных только backend-хранилище (volume). Добавлена очистка legacy-кэша браузера `berkut.accesses.users`.
- Для меню `Доступы` добавлено полное логгирование действий в `Логи`: `create/edit/supplement/blocked/unblocked/delete/dismissal/test/cleanup`.
- Технические события отправки уведомлений по доступам убраны из браузерной консоли и фиксируются в `Логах`.

### Уведомления
- Вкладки `Каналы` и `Настройки` приведены к общей системе вкладок, как в `Настройках`.
- Для вкладок добавлены отдельные ссылки:
  - `/notifications/channels`,
  - `/notifications/settings`.
- Уведомления перенесены из вкладки `Мониторинг` в отдельный пункт меню для удобства и интеграции с `Доступами`.
- Цвета карточек и фреймов скорректированы под общий стиль приложения.
- В `Уведомления -> Настройки` добавлен выбор канала для отправки уведомлений по `Доступам`.
- В типы уведомлений по `Доступам` добавлен тип `Увольнение`.
- Исправлена отправка уведомлений по событиям `Доступов` при выбранном канале: события отправляются через API-настройки модуля без локальной блокировки.
- Исправлен текст подтверждения сохранения в `Уведомления -> Настройки`: теперь отображается сообщение про настройки уведомлений, а не мониторинга.
- Для отправки событий `Доступов` расширены права API и добавены явные сообщения о причине пропуска отправки (disabled/type/channel).
- Ошибки отправки уведомлений по `Доступам` теперь отображаются через toast поверх модальных окон; для событий с выбранным каналом фиксируется запись в `Истории доставок` со статусом `sent/failed/skipped`.
- Операции `Доступов` переведены на жесткую серверную персистентность: при ошибке сохранения изменения откатываются, чтобы не оставались только в браузерной сессии.
- Для каждой записи `Доступов` добавлена кнопка `Тест` отправки уведомления.
- Дополнена русификация журнала аудита для действий `notifications.settings.update`, `notifications.accesses.send`, `accesses.update`, `services.catalog.update`, `tags.catalog.update`, `classifications.catalog.update`.
- Смягчены права API для `GET/PUT /api/accesses` (добавлен fallback на `app.view`), чтобы устранить ложные ошибки сохранения у ролей с доступом к вкладке.
- Для меню `Уведомления` добавлено полное логгирование в `Логи`: просмотр настроек и отправка событий по доступам (включая статусы `sent/failed/skipped` и причину).

### Справочники
- Каталог `Сервисы` в настройках переведен с browser `localStorage` на backend API (`/api/services`) и хранение в БД/volume.
- Для legacy-данных сервисов в браузере добавлена автоматическая миграция на серверный источник при загрузке каталога.
- Каталоги `Теги` и `Классификации` в настройках переведены с browser `localStorage` на backend API (`/api/catalog/tags`, `/api/catalog/classifications`) и хранение в БД/volume.
- Для legacy-данных `berkut.tags` и `berkut.classifications` добавлена автоматическая миграция на серверный источник с очисткой браузерных ключей.

### Настройки
- Убран внешний задний фрейм-обертка на странице `Настройки`: сохранены только внутренние рабочие фреймы.

### Интерфейс
- Добавлено сворачивание/разворачивание бокового меню с отображением иконок вкладок в свернутом режиме.
- В свернутом меню оставлены быстрые действия внизу: `Профиль`, `Выйти`, версия приложения.

### Мониторинг
- Остановлен фоновый polling карточки монитора и статистики движка при уходе со страницы и при недоступности backend: убраны циклические `401`/`Failed to fetch` в консоли при остановленном контейнере.
- После создания/редактирования монитора добавлен явный `check-now` и ожидание первого ответа, чтобы статус/индикаторы/график обновлялись сразу.
- Исправлен `500` на `GET /api/monitoring/certs`: null-поля сертификатов (`common_name`, `issuer`) безопасно обрабатываются на SQL-уровне.
- Ускорена первичная ручная проверка монитора: `check-now` теперь коротко ожидает свободный воркер вместо мгновенного `busy`, а таймаут ручной проверки ограничен для более быстрого первого результата в UI.

### Бэкапы
- Убрана периодическая авто-перезагрузка overview: данные обновляются при входе на вкладку и по кнопке `Обновить`, что устраняет спам `backups.list/backups.read` в `Логах` и повторяющиеся `ERR_CONNECTION_REFUSED` в консоли при остановленном backend.

### Версия и документация
- Версия приложения обновлена до `1.2.0`.
- Обновлены версионные маркеры в README и документации (`docs/*`) до `1.2.0`.
