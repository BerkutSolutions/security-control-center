# Журнал изменений

## 1.1.6 — 27.03.2026

### Доступы
- Добавлена вкладка `Доступы` в левом меню.
- Добавлена вкладка `Сервисы` в `Настройки` для управления справочником сервисов.
- Реализован экран `Доступы` в формате единого фрейма:
  - сверху кнопка `Добавить`,
  - снизу кликабельная таблица пользователей по столбцам.
- Создание пользователя переведено в модальное окно (`Добавить`).
- В карточках `Роли` заменены на `Должность` и `Отдел`.
- `Дополнить` теперь изменяет только профиль (`Должность`, `Отдел`), без изменения пользователя.
- Улучшен визуал карточек и модального окна просмотра доступа.
- В модальном окне просмотра:
  - кнопка `Заблокировать/Разблокировать` перенесена в хедер рядом с `x`,
  - убрана кнопка `Закрыть`,
  - лента активности сделана в 2 столбца.

### UX и производительность
- Убрана задержка первичной отрисовки после refresh: `/api/app/meta` загружается в фоне, не блокируя рендер.
- Добавлена анимация закрытия модалок для закрытия через:
  - крестик (`data-close`),
  - клик по backdrop,
  - клавишу `Esc`.

### Версия и документация
- Версия приложения обновлена до `1.1.6`.
- Синхронизированы версионные маркеры в README и docs до `1.1.6`.
- Обновлены wiki-разделы по вкладкам и функциональным блокам с учетом `Доступы` и `Сервисы`.

### Финальные правки 1.1.6
- Экран `Доступы` переведен в формат одного фрейма: сверху кнопка добавления, снизу кликабельная таблица по столбцам.
- Сервисы в таблице `Доступов` отображаются цветными плашками со стабильным цветом для каждого сервиса.
- В модалке `Дополнить` оставлено дополнение только сервисов; должность/отдел больше не изменяются через этот сценарий.
- В `Дополнить` показываются только сервисы, которых у пользователя еще нет; если добавить нечего — кнопка дополнения блокируется и выводится подсказка.
- Данные вкладки `Доступы` сохраняются через `/api/accesses` в БД и попадают в модуль `Бэкапы` (scope `accounts`).
- Исправлено предупреждение Docker Compose `The "i" variable is not set` в `certgen`-скриптах (`docker-compose.yaml` и `docker-compose.local.yml`) через корректное экранирование shell-переменных.
