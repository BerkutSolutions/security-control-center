# Журнал изменений

## 1.2.2 — 30.03.2026

### Согласования
- Исправлено открытие согласований для отчётов:
  - в UI добавлено определение сущности `документ/отчёт` с fallback на `/api/reports/{id}`, поэтому больше нет 404 на `/api/docs/{id}` для отчётов;
  - в списке и карточке согласования корректно показывается название отчёта вместо `#id`.
- Для отчётов исправлена индикация статуса согласования:
  - в списке отчётов статус теперь берётся из `doc.status` для approval-состояний (`review/approved/returned`), как в документах;
  - после отправки на согласование и после решения выполняется авто-обновление списка отчётов.
- Исправлены уведомления в боковом меню для отчётов:
  - счётчик и список теперь учитывают только активные статусы (`draft/review/returned`) по приоритету `doc.status`;
  - утверждённые отчёты больше не попадают в уведомления.
- Убраны ложные 404 в UI на старых/неактуальных записях:
  - API выдаёт `doc_type` в списке согласований, фронт больше не стучится в неверный endpoint;
  - из листинга исключены согласования по soft-delete документам.
- Исправлена очистка согласований в `Настройки -> Обслуживание`:
  - очистка теперь удаляет не только workflow-записи (`approvals`), но и export-согласования (`doc_export_approvals`);
  - режим завершённых очищает утверждённые/отклонённые/просроченные/использованные записи, режим «все» очищает полностью;
  - добавлена принудительная очистка осиротевших записей (`approval_participants`, `approval_comments`, `doc_export_approval_decisions`) для legacy-баз.

### Версия и документация
- Версия приложения обновлена до `1.2.2`.
- Обновлены версионные маркеры в README и документации (`docs/*`) до `1.2.2`.
