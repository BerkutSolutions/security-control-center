# DLP в Berkut SCC

Версия: `1.2.2`

## Назначение

DLP-подсистема в Berkut SCC снижает риск утечек при работе с документами и отчетами:

- блокирует копирование (copy/cut/context menu, горячие клавиши),
- фиксирует попытки скриншотов и события потери видимости окна,
- пишет события в аудит и поведенческую модель риска.

## Где настраивается

`Настройки -> Укрепление безопасности -> DLP фрейм`

Доступные параметры:

- `Запретить копирование защищенного контента`
- `Пытаться блокировать скриншоты`
- `Режим применения блокировок`:
  - `Только защищенные (гриф/теги)`
  - `Ко всем документам/отчетам`
- `Модули защиты` (scope):
  - `Документы`
  - `Отчеты`

По умолчанию:

- блокировка копирования = включена,
- блокировка скриншотов = включена,
- режим = `только защищенные`,
- scope = `документы + отчеты`.

## Как определяется защищенный контент

В режиме `Только защищенные (гриф/теги)` объект считается защищенным, если:

- уровень грифа `>= 2`, или
- у объекта есть хотя бы один тег классификации.

В режиме `Ко всем документам/отчетам` проверка грифа/тегов не используется.

## Как работает блокировка копирования

Для выбранных модулей и подходящих объектов:

- перехватываются `copy`, `cut`, `contextmenu`,
- перехватываются сочетания `Ctrl/Cmd + C/X/A`,
- применяется режим `no-copy` (`user-select: none`) для панели просмотра/редактирования,
- при срабатывании пишется security-событие.

События:

- `doc.security.copy_blocked`
- `report.security.copy_blocked`

## Как работает обработка скриншотов

Для выбранных модулей и подходящих объектов:

- обрабатывается `PrintScreen` (`keydown`/`keyup`),
- при `visibilitychange=hidden` также фиксируется попытка,
- показывается privacy shield (визуальная реакция),
- событие пишется в аудит и в риск-модель.

События:

- `doc.security.screenshot_attempt`
- `report.security.screenshot_attempt`

## Интеграция с поведенческой моделью

Security-события DLP дополнительно пишутся в `user_behavior_events`:

- `dlp.copy_blocked`
- `dlp.screenshot_attempt`

Они учитываются в активности пользователя в:

`Настройки -> Укрепление безопасности -> Анализ активности`

Отображаются как DLP-сигнатуры:

- блокировки копирования за 10 минут,
- попытки скриншотов за 10 минут,
- соответствующие причины в блоке `reasons`.

## Аудит и трассировка

Настройка DLP логируется действием:

- `settings.hardening.dlp.update`

Записи по событиям в логах:

- `doc.security.copy_blocked`
- `doc.security.screenshot_attempt`
- `report.security.copy_blocked`
- `report.security.screenshot_attempt`

## Важные ограничения

DLP в браузере не может гарантированно заблокировать скриншот на уровне ОС/внешних устройств.  
Реализуется практический уровень защиты:

- предотвращение большинства стандартных сценариев копирования,
- фиксация попыток,
- аудит и сигнатуры риска для дальнейшей реакции.

## Рекомендации для production

- оставлять блокировки включенными по умолчанию,
- для чувствительных контуров использовать режим `Ко всем`,
- регулярно проверять DLP-события в логах и блоке анализа активности,
- сочетать DLP с RBAC, классификацией и step-up политиками.
